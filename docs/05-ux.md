# 05 — Product experience and frontend

## Design language

Ported from the reference app: a **custom design system** — CSS Modules + CSS
variables, no component framework. Design tokens (`webui/src/theme/tokens.css`):
light/dark palettes via `[data-theme]`, a 4px spacing grid, Inter + JetBrains Mono
type scale, calm motion tokens honoring `prefers-reduced-motion`, square-cornered
opaque progress bars, self-hosted fonts. Theme toggling sets
`document.documentElement.dataset.theme` and persists to `localStorage`.

Global shell: left `NavRail` (⌂ Home, ⚙ Settings; badge = count of sessions currently
analyzing) → `<main>` outlet → bottom `StatusBar` (hub connection dot, Ollama model
pill, queue depth, theme toggle).

## Analysis progress — `/sessions/:id/progress`

- Vertical **stage list** (clone → index/embed → map → outline → sections → diagrams
  → quizzes → finalize): ✓ done / active square progress bar / pending dot, per-stage
  elapsed time and detail counts. Driven by `AnalysisStageChanged`/`AnalysisProgress`;
  snapshot on mount + `GetEventsSince` catch-up.
- **Narration ticker**: capped-height monospace log of `AnalysisNarration` events —
  "› Detected pnpm monorepo with 27 packages", "› Found CI: build_and_test.yml" — the
  "expert reading over your shoulder" moment that makes minutes feel purposeful.
- Queued state shows queue position. **Early-entry banner** on first `SectionReady`:
  "Intro is ready — start reading now"; remaining sections show as `generating` in the
  TOC and pop in live. `AnalysisCompleted` auto-navigates (3 s toast with cancel).
- ETAs are honest: derived from the stored plan plus live tokens/second measurement.

- **TOC** (left, ~280px): per-section glyphs — ✓ completed · ● reading · ○ unread ·
  ─ skipped (dimmed) · ◐ generating (pulsing, disabled). Deep dives nest under their
  parent. Header: overall completion bar + estimated remaining minutes.
- **Content column** (max-width 760px reading measure): blocks in order — markdown
  (GFM), code excerpts (JetBrains Mono, Shiki highlighting, "View on GitHub ↗"
  SHA-pinned link), callouts, staged diagrams.
- **Pacing bar** (sticky): Skip section (marks `skipped` — counts separately from
  completion) · Prev/Next · Mark complete. Scrolling to a section's end auto-marks
  `read`; `completed` is always explicit (button or quiz ≥ 75 %). Keyboard: `j/k` or
  `←/→` for sections, `[`/`]` for diagram stages.
- **"Go deeper"**: 1–3 chips per section end, plus contextually on diagram nodes.
  Pre-generated dives navigate immediately (depth-first detour; "Next" returns to the
  parent flow). On-demand dives flip the chip to a progress state ("the expert is
  sketching this out…", ~30–60 s — the RAG context already exists) via `DeepDiveReady`.
- **Chat panel** (right, ~360px, collapsible slide-over): see below.

## The progressive whiteboard (signature interaction)

**One diagram per tour stop, rendered once, staged by CSS dimming.**

- The client renders the *full* Mermaid document once (mermaid v11 as a direct
  dependency, themed from the CSS variables and re-themed on `[data-theme]` change).
  Not-yet-revealed nodes/edges get a `.ghost { opacity: .12 }` class. Layout never
  jumps between stages, and the learner honestly sees that more is coming.
- Stage metadata comes from the `DiagramSpec.reveal` stage-sets (see
  [01-analysis-pipeline](01-analysis-pipeline.md)); stage *k* shows the union of
  stages 0..k. Each stage pairs a reveal set with a narration paragraph beside the
  SVG; a stepper ("Stage 2 of 5", ◀ ▶, arrow keys) drives it.
- Sequence diagrams (scenario walkthroughs) reveal message-by-message with the same
  ghosting.
- Clicking a revealed node opens a popover: node summary, **Go deeper →** (linked
  deep-dive section), **Ask the expert** (opens chat prefilled with "Explain the role
  of `<node>`").
- Rendering is reliable by construction: the SVG comes from spec-rendered Mermaid
  (validated JSON in, sanitized labels out), so there is no LLM-written Mermaid to
  fail parsing. If a spec fails referential validation twice, the block degrades to
  markdown narration as a numbered list.

## Quizzes

Inline card at section end — a comprehension checkpoint, never an exam, always
skippable.

- **3–4 deterministic questions** (`single` / `multi` / `boolean`) grade instantly by
  comparison — zero LLM risk. Each stores an explanation shown after answering.
- **At most one short answer**, graded by the smallest reliable LLM task: *binary
  coverage per rubric key point* ("does this text mention X"), emitted as strict JSON
  via Ollama structured output, one retry; on second failure the answer is
  **ungradable and excluded from the score — never silently wrong**. No essay
  grading, no calibrated scalar scores (small local models are poor at those).
- Answer keys and rubrics never leave the server (`GET /quizzes/{id}` strips them).
- Feedback per miss: the explanation plus a **reread deep link** ("You missed how
  routing is resolved — reread *Architecture → The request pipeline*, stage 3") that
  navigates and scroll-highlights the target block.
- Score ≥ 75 % auto-marks the section `completed`. Unlimited retakes; best score kept
  (TOC glyph tooltip).

## Q&A chat panel

- One default thread per session, created lazily on first message; "+ new thread" for
  fresh contexts (simple dropdown switcher).
- Composer with "include current section as context" toggle (default on).
- Assistant messages stream token-by-token (direct DOM append via the streaming
  buffer, no query round-trip), blinking caret, Stop button (cancels generation,
  keeps partial text).
- **Citations**: after the answer, cards with monospace path + line range, hover/click
  → inline peek of the snapshotted lines, ↗ → GitHub deep link at the pinned SHA.
  Inline `[1]`, `[2]` markers scroll to their card. The prompt only permits citing
  retrieved chunk ids; the Gateway maps ids to verified paths/lines and strips
  unresolvable markers.
- If asked while indexing is still running, a "knowledge base still indexing" banner
  sets expectations; queue-position feedback covers waits behind a batch job.

## Frontend structure

```
webui/
  openapi.json                    # checked in; npm run gen:api → api/schema.d.ts
  src/
    main.tsx · App.tsx            # router + QueryClient
    theme/tokens.css              # design-token base (ported)
    api/      client.ts (openapi-fetch) · schema.d.ts · events.ts (envelope types)
    auth/     useAuth.ts · AuthGate.tsx     # /api/config → DevBypass|SharedGate|Oidc
    services/ liveEvents.ts                 # SessionHub singleton (ported pattern)
    store/    ui.ts (theme+toasts) · tutorial.ts · chat.ts     # Zustand, UI-only
    components/  Button Card Chip ProgressBar Modal Toaster Markdown CodeBlock …
    features/
      shell/     Shell · NavRail · StatusBar
      home/      Home · SessionList · NewSessionForm · ResumeCards
      progress/  AnalysisProgress · StageList · NarrationTicker
      tutorial/  TutorialLayout · SectionNav · SectionView · BlockRenderer
                 blocks/ (MarkdownBlock CodeExcerpt StagedDiagram Callout DeepDiveChip)
                 PacingBar
      quiz/      QuizCard · QuestionRow · ResultFooter
      chat/      ChatPanel · MessageList · StreamingMessage · CitationCard · Composer
      settings/  Settings
    test/ setup.ts                # Vitest + Testing Library; Playwright in webui/e2e/
```

**State split (strict):** TanStack Query owns *all* server state (keys per entity;
mutations with optimistic TOC updates). Zustand holds only ephemeral UI: theme/toasts,
chat-panel/TOC/diagram-stage state, and per-message streaming buffers (appended by the
live-events listeners, cleared on `QaMessageCompleted`).

**Responsive posture:** desktop-first (it's a study tool) with defined degradation —
< 1100px the chat becomes a full-screen sheet; < 900px the TOC collapses to a top
drawer, content single-column, diagrams get pinch-zoom/pan; Home stacks vertically.
